# 卡片工作台 v1

卡片工作台接口与使用说明。支持中尺寸卡片的数据和发布更新，实现边界见[实现概览](implementation.md)。排版描述见[JSON Schema](card-design.schema.json)及[行情示例](../examples/cards/market-design.json)。

## 使用流程

面向首次使用的分步说明、两种接入方式、多卡数据关系与完整AI示例见[创建与接入卡片](web-studio-guide.md)。工作台默认打开“我的卡片”管理页。新建卡片提供 AI 辅助生成：填写地址、密钥和需求后生成说明，贴回模型返回的 JSON 即创建数据源和草稿卡片；密钥不进入说明。数据源管理仍保留专业添加。

1. 手机连接服务器并填写设备名称。Web管理员登录同一服务器。
2. “我的卡片 → 新建卡片”填写名称，选择独立数据源或共用已有源；选择读取JSON/API或工具主动上报，再选起始布局。已有源可在“数据源管理”编辑、写入内容或立即采集。
3. 数据未接入时展开操作指引，可按字段手动填写、复制上报地址或配置API。设计页直接选择显示项及实际字段，预览随之更新；组件树和复杂布局在“高级布局”中。缺数据或字段未匹配时提示并阻止发布。
4. “AI辅助设计”有完整任务进度输入/输出及效果示例。填写排版要求，复制完整说明给所选模型，粘贴返回JSON并校验预览。错误保留输入，成功后可回可视化调整；不会自动发布或调用外部AI。
5. 保存草稿只影响Web；“发布到设备”才生成新的手机可读版本。每卡“接入与订阅”提供脚本地址/完整curl、手机订阅码/链接、关联卡片及订阅设备管理。切换未保存设计时提示保存或放弃。
6. 手机“卡片 → ＋ → 通过订阅码导入Web卡片”，先选择发布服务器，粘贴码或链接。码属于该服务器；链接会校验与所选服务器匹配。需已有有效绑定，不自动将凭据发往链接中的任意地址。
7. 导入后使用完整设计，无需再排版。手机可调整名称、外观及叶组件的显隐、显示别名、小数位、字号，亦可逐项或全部恢复跟随Web。
8. 通过系统添加 Vao Push 小组件并选择已保存卡片。桌面刷新时机由 iOS 系统根据电量、网络和预算调度。

手机“＋”只提供本机消息模板和Web订阅导入。行情、服务器状态、进度等功能数据卡片统一在本工作台设计；手机只做轻量微调。首页默认收起的“示例”仅展示效果，不会创建业务数据或订阅。既有本机功能卡片兼容保留。

## 多卡滑动切换

支持采用 iOS 系统智能叠放：分别添加同尺寸的Vao Push小组件，各选一张已保存卡片（可以来自不同服务器），拖叠后上下滑动。每张仍独立读取数据并保留微调；可在系统编辑叠放中关闭智能轮换。当前每个组件实例选一张卡片，不在单组件内部实现自定义滑动容器或一次多选自动创建叠放。创建/编辑叠放由用户通过系统完成。

平台依据：[WidgetKit策略与智能叠放](https://developer.apple.com/documentation/widgetkit/developing-a-widgetkit-strategy)。叠放体验、每张卡片数据更新及完整后台矩阵分别验收，不扩大一次成功样本的结论。

## 数据、发布与本机微调

卡片数据源属于管理员，但实际状态流保存在独立内部作用域。早期共享账号设备不会自动继承原始数据可见范围。设备通过订阅获取某张卡片的配置与快照；共享读取凭据只能读取已订阅卡片，不能枚举管理配置、生成码或订阅其他卡片。

数据revision、草稿revision、发布revision、本机微调分别保存。发布兼容变更后，未微调项跟随Web；本机名称/精度等继续保留。组件稳定id须保持；若被微调组件被移除或改变类型，客户端保留上次可用设计并提示，可恢复跟随Web后同步。未知版本/组件不静默忽略。网络失败保留已验证缓存与原时间；订阅明确撤销后隐藏卡片数值。

删除最后一个本地副本会先请求取消订阅；离线失败不会伪称已取消。复制的本地卡片保留同一订阅引用、各自独立微调。订阅与默认消息接收列表互不改变。

## 管理员删除卡片与数据源

“我的卡片”列表及每卡“接入与订阅”页可删除单张卡片；“数据源管理”可删除未被使用的数据源。先查看影响范围，再确认永久删除；取消不更改资源。数据源只要存在任何关联卡片（包括未发布草稿）就不能删除，页面列出这些卡片并提供查找入口；没有强制删除或连同卡片批量删除选项。

删除卡片会移除其草稿、已发布设计、订阅码和设备读取授权，保留数据源及其他卡片。清空所有引用后，才可删除数据源；这会清除该源最新数据、采集配置及专属写入凭据，停用原上报地址。手机已保存的卡片会在下次读取或同步时显示不可用，离线缓存和系统桌面不会立即消失。默认消息接收列表及普通消息历史不受影响。当前没有回收站或控制台恢复入口。

管理接口先GET对应`/deletion`取得`confirmation_token`，再DELETE资源并原样传入`If-Match`。缺少确认返回428；草稿/发布版本、关联卡片、订阅设备或新生成的码发生变化时返回412，须重新预览；数据源仍有卡片引用返回409 `source_in_use`。普通数据上报不改变确认版本。确认摘要在JSON中返回，避免代理改写ETag影响比较。预览仅对所属Web管理员开放，不缓存；删除仍校验Origin和CSRF。

## 描述格式与限制

- schema_version=1，name，family（small/medium/large/extraLarge），可选theme（system/light/dark），layout。
- 组件：row、column、grid、list、text、number、badge、divider、spacer、chart。支持受控字体、字重、颜色/背景、间距、内边距、圆角、对齐和正负颜色规则；不执行HTML、CSS、JavaScript或Swift。
- 容器children；重复列表source=items、row、limit；字段绑定fields.key，图表绑定series.key。K线须由源提供真实OHLC。
- 样式代码最多24KiB、6层、64组件；全局id唯一；容器1至12子项，网格1至4列，列表1至20项。手机按尺寸限制可见行数，小1、中3、大/超大最多12，保持原生布局，不提供任意网页滚动控件。
- 字号10至32，小数位0至18，间距/内边距/圆角0至24。十进制值保留字符串精度，Web预览按原生半偶数舍入处理。像素级结果受系统字体和边距影响。
- 图片/任意网页嵌入、自由脚本、在线LLM调用、二维码扫描、删除回收站、自由数据源切换和跨设备本机微调云备份当前未提供。当前提供码和链接粘贴导入。

## API 数据源

HTTP源当前使用GET读取公网HTTPS JSON，不跟随重定向，不访问私网/回环/链路本地地址；DNS解析后校验并固定目标连接。允许Authorization、X-API-Key、Accept请求头，鉴权加密保存。编辑配置时省略headers保留，{}清空；读取只返回配置是否存在。

记录/列表路径及字段路径支持点号和数字下标，如data.items、data.price、result.items[0].value；不执行JSONPath表达式。列表需提供稳定字符串项目标识，最多20项。映射类型沿用现有协议，数值保持十进制字符串，不提供任意业务计算或交易策略。

HTTP源的source_updated_at表示本次采集时间；API自身的业务时间可映射为单独字段，不把采集时间当作交易所事件时间。映射完全缺失或响应无效时保留原内容；明确的空列表显示为空。

响应最多256KiB、超时10秒。采集周期60至86400秒；独立Worker轮询，失败保留上次有效内容和时间并记录原因。成功状态有效期为采集周期的两倍。采集周期不代表iOS刷新频率。

外部上报源可PUT最简状态到专属地址，省略schema_version和source_updated_at时由服务端补齐。上报Key固定单个流，只写状态，无消息发送、读取或管理权限。

## 已实现端点

Web接口使用管理员会话及写请求Origin/CSRF校验。参数与响应见[OpenAPI](openapi.json)。

| 端点 | 用途 |
| --- | --- |
| GET/POST /v1/card-sources | 列表/创建数据源 |
| GET/PUT /v1/card-sources/{id} | 读取脱敏配置/修改配置 |
| GET /v1/card-sources/{id}/deletion | 预览数据源引用及删除确认版本 |
| DELETE /v1/card-sources/{id} | 条件删除无卡片引用的数据源，If-Match为确认版本 |
| GET /v1/card-sources/{id}/access | 管理员读取上报地址 |
| PUT /v1/card-sources/{id}/data | Web手动更新共享数据 |
| PUT /v1/card-sources/{id}/enabled | 启停HTTP采集 |
| POST /v1/card-sources/{id}/poll | 立即采集 |
| PUT /v1/card-data/{key} | 外部工具更新固定数据源 |
| GET/POST /v1/cards | 列表/创建草稿 |
| POST /v1/cards/validate | 校验并规范化代码，不保存 |
| PUT /v1/cards/{id} | 保存草稿，If-Match为"draft-{draft_revision}" |
| GET /v1/cards/{id}/deletion | 预览卡片及订阅设备影响、删除确认版本 |
| DELETE /v1/cards/{id} | 条件删除单张卡片，If-Match为确认版本 |
| POST /v1/cards/{id}/publish | 条件发布对应草稿，使用相同版本头 |
| POST/DELETE /v1/cards/{id}/codes | 生成/撤销导入码；撤销码不影响已有订阅 |
| GET /v1/cards/{id}/subscribers | 管理员查看订阅设备 |
| DELETE /v1/cards/{id}/subscribers/{device} | 撤销该设备本次订阅；持有效码可重新申请，需阻止再申请时同时撤销旧码 |
| POST /v1/cards/redeem | 私有设备凭据兑换码，同设备重复导入不重复扣次数 |
| GET /v1/card-subscriptions | 私有设备凭据枚举本设备订阅 |
| GET /v1/card-subscriptions/{id} | 私有/共享读取凭据取得已授权发布配置与快照 |
| DELETE /v1/card-subscriptions/{id} | 私有设备凭据取消本设备订阅 |

每管理员最多32数据源、64卡片，每设备最多16张订阅；现有状态64KiB、字段/序列限额继续适用。订阅码VP-加24位十六进制，1小时有效、最多10台设备；属于所在服务器及管理范围。读取授权在兑换后绑定设备，日后无需重复输入码。权限轮换与备份策略可按实际自建部署需求配置。
