# Vao Push 产品与技术设计

Vao Push 将消息通知、结构化数据和桌面卡片分成独立资源。发送方只需要按协议提交消息或最新数据，用户在 Web 工作台配置字段和布局，App 与 Widget 根据已保存的卡片展示内容。

## 产品组成

- **服务端**：接收请求、验证凭证、保存历史与最新状态、创建持久发送任务，并向 APNs 发起请求。
- **Web 控制台**：管理员登录后管理设备、默认接收列表、消息发送、数据源、卡片草稿和发布订阅。
- **iOS / iPadOS App**：连接任意自建服务器、查看消息和数据、导入卡片并进行有限的本机微调。
- **Widget 与通知扩展**：使用共享 App Group 存储，在系统允许的执行时机读取已发布卡片和最新快照。

## 日常流程

1. 在服务器上安装服务端并完成端口和 HTTPS 配置。
2. 在 App 中填写服务器地址和设备名称，完成设备注册。
3. 在 Web 中选择接收设备，复制消息地址或数据地址给自动化工具。
4. 在 Web 创建数据源和卡片，预览后发布，再通过订阅入口导入 App。
5. 用户按系统流程将所选卡片添加到桌面。

普通用户不需要填写 Apple Key ID、Team ID、Bundle ID 或 `.p8` 私钥。正式安装包会在安装阶段携带官方推送身份；源码和 Web 页面不会收集这些内容。

## 资源隔离

消息历史、数据源最新状态、发布卡片、设备订阅和本机微调分别保存。数据更新不会覆盖用户的字段别名、顺序、主题或字号设置；一份数据可以绑定多个卡片，删除数据源前必须没有任何草稿或已发布卡片引用它。

每台设备拥有独立的内部作用域和凭证。发送 Key 只用于发送，读取凭证只允许读取已授权的卡片或数据。服务器对用户归属、设备状态、订阅关系和版本条件进行校验。

## 部署与安全边界

服务端使用 Go、PostgreSQL、systemd 和 Docker。数据库默认只绑定本机；对外只开放用户选择的 API/Web 端口。HTTPS 可由 Caddy、已有反向代理或用户提供的证书完成。生产部署应使用受信 HTTPS，不应把数据库端口直接暴露到公网。

服务端的 APNs 身份由部署者的正式安装包导入，并在数据库中加密保存。消息正文会经过用户自己的服务器和 Apple 的推送链路；业务 API 密钥由用户自行管理，不存入 App。

## 当前边界

当前源码适合审阅、构建和自建验证。公开账号体系、托管式多租户服务、计费、自动找回、严格固定频率刷新和所有低电量/强退场景，均不应视为已经交付的公共服务。
