# 简单接入与两路发送

当前创建规则：手机本机新建只提供最近消息模板；功能数据卡片在Web工作台创建数据源、设计并发布，通过订阅码导入。手机显示的数据上报地址已移入兼容接口，供已有本机数据卡片使用；新卡片的上报地址从Web数据源复制。下文旧设备数据接口继续兼容。

当前默认接入方式，不要求客户端登录、配对、建分组、预建数据流或手动配置发送范围。实现与验证边界见 [implementation.md](implementation.md)。

## 使用

1. 手机添加 Vao Push 服务器的 HTTP 或 HTTPS 地址，填写“此设备的名称”（必填，例如工作手机）；服务器显示名称可不填。
2. App 自动注册本设备，得到该服务器下专属的发送 Key。可同时添加多台服务器。
3. 在 Web 勾选并保存默认消息接收设备，复制统一的自动推送地址交给任意工具；也可临时选择设备手动发送。设备详情另提供该设备专属地址。
4. 手机“卡片 → ＋”可创建最近消息模板，或导入Web订阅码。功能数据卡片在Web工作台创建数据源、设计并发布；手机导入后可轻量微调。保存后再通过系统添加到桌面。

手机不需要 Web 账号或配对码。Web 是服务器管理员控制台，保留密码、会话与来源保护。自建服务器管理员可以管理该服务器上的接入设备；这不是公开多租户的私人用户 Web 账号服务。

设备名称用于辨认，实际身份仍由随机凭据和稳定设备标识确定。服务器详情可修改已有名称，保留绑定、历史、卡片与默认接收关系。Web同时显示名称及设备标识；重名也可区分。客户端名称最多40字、120 UTF-8字节，不含换行或控制字符。

## 发送

消息：在 Web 保存默认接收列表后，复制“自动推送地址”。向该地址 POST 内容，服务端按保存的列表自动分发，不需要请求方逐台列设备。修改列表不改变地址；新设备不会自动加入。未选入默认列表的设备仍可通过 Web 临时接收，且不会因此被加入默认列表。

```http
POST /v1/push/{key}
Content-Type: application/json
```

```json
{"title":"任务完成","body":"这是一条来自任意工具的提醒。"}
```

卡片数据：在Web工作台创建外部上报数据源并复制专属地址，随后按以下形式提交：

```http
PUT /v1/card-data/{source_key}
Content-Type: application/json
```

```json
{"fields":{"progress":{"type":"percent","label":"完成率","value":"68"},"status":{"type":"text","value":"运行中"}}}
```

同一数据源地址整份替换最新状态。随后在Web设计卡片、发布并生成订阅码，供需要的设备导入。每次提醒独立保留；更新卡片数据不会产生普通消息历史，也不会更改手机卡片配置。数值采用十进制字符串，完整字段、项目和图表协议见 [API](api-v1.md)。

兼容已有本机数据卡片的设备地址为`PUT /v1/state/{key}/{data_id}`，仍按固定data_id覆盖。手机详情中的该地址已放入兼容入口；新功能卡片使用Web工作台的数据源地址。

最简消息可省略 `schema_version` 和 `target`。Web 自动推送 Key 对应已保存接收列表；手机复制的设备专属 Key 仍只对应该设备。两者使用同一路径，但权限不混用：自动消息 Key 不可在正文覆盖目标，也不具备卡片数据写权限。最简状态可省略 `schema_version`（默认 1）和 `source_updated_at`（默认服务端接收时间；需要表达原业务时间时应显式提供）。`Idempotency-Key` 可选；重试同一逻辑请求建议保留相同键。202 只表示保存并排队，不表示手机已显示。

也可使用 `Authorization: Bearer {key}` 调用 `POST /v1/messages`；设备专属 Key 还可调用 `PUT /v1/widgets/{data_id}/state`。URL 方式与 Bearer 方式共用保存和分发服务，不可通过请求体改变 Key 授权的接收范围。

发送地址包含秘密，只有需要发送内容的工具应持有。Key 只有写权限，不能读取消息、读取快照、替换 APNs token 或解绑设备。移除设备同时撤销其发送与读取凭据。

## 自动注册与兼容

`POST /v1/register` 接收 `device_name`、`platform: "ios"` 和 App 生成的随机 64 位十六进制 `registration_token`。后者是保存在私有 Keychain 的注册恢复秘密；服务端按其摘要串行处理，网络失败或响应丢失后重试返回同一注册，不能使用设备名称或公开设备 ID 恢复身份。

返回 `server_id`、内部 `account_id`、`binding_id`、`device_token`、`read_token`、`send_key`、`expires_at`。内部 account_id 只用于数据隔离，手机不显示“账号”。新注册设备具有各自的状态命名空间：不同设备的同名 data_id 不混用。服务端保存凭据校验摘要，并用部署主密钥加密保存可恢复的注册结果；解密主密钥必须随数据库私有备份。

App 私有凭据负责本设备注册、同步、暂停和移除；共享 Keychain 只向 Widget 提供受限读取凭据。注册秘密在本地绑定成功后删除；重试不新建设备。当前自动注册凭据有效 10 年，支持提前撤销，未实现无感轮换。

旧配对设备保持原有 ID、缓存、卡片与历史。首次升级同步通过 `GET /v1/device/access` 补齐发送 Key；旧设备原有共享状态作用域不做隐式迁移。早期分组、范围凭据和配对 API 为兼容保留，不再出现在首版正常使用流程。

## Web

保留发送消息、更新卡片数据、接入设备、发送记录、服务器设置五个入口。状态可用字段表单发送，复杂项目和图表使用 JSON。已有内容先读取再修改：ETag 防止覆盖别人刚写入的版本；新 ID 用 `If-None-Match: *` 防止误覆盖已有内容。Web 自动生成重试幂等键。

消息使用设备复选框，支持任意多选、全选和清空，显示已选数量。手动提交 `target: {"device_ids": ["dev_example_a", "dev_example_b"]}`，一次事务保存消息与逐设备任务；所有目标必须归属当前管理员且可接收，出现失效目标则整次拒绝，避免悄悄少发。重复 ID 去重，同幂等键重试不重复入队。旧的 `device_id`、`all_devices` 和分组目标继续兼容。列表及全部设备仅接受 Web 管理会话，设备专属 Key 不扩权。状态更新仍选择单台设备。

点击“保存为自动推送接收设备”持久保存默认列表；“使用已保存列表”恢复已保存的勾选。自动请求取当次有效的已保存设备，跳过后来暂停或撤销的设备；没有有效目标返回422。保存空列表暂停自动分发，地址保持不变。已经接受的请求重试沿用原目标，修改列表只影响新的逻辑请求。

配置接口为 `GET/PUT /v1/message-route`，仅管理员会话可用。PUT 正文为 `{"device_ids": [...]}`，使用 `If-Match: "route-{revision}"` 防止过期编辑覆盖；初始 revision 为0。返回 revision、保存的 device_ids、configured，配置后还返回 message_url。revision 表达源站配置版本；Web 从该值构造条件头，避免压缩代理改写 HTTP ETag 影响保存。地址秘密加密保存在数据库，校验仍用摘要；默认消息凭据有效10年，不能读取历史、控制设备或改列表。

示例：A、B、C 都保持绑定，默认列表为 A、B。自动任务只通知 A、B；Web 临时勾选 C 可单独通知 C，或勾选三台群发。手动选择不会更改默认列表，也不需要将 C 暂停或解绑。

Web 请求状态时通过 `device_id` 选择设备，服务端校验此设备是否由当前管理员管理，再使用其数据作用域。管理员从 `GET /v1/devices/{id}/access` 获取发送地址；不能通过输入任意 ID 取得其他管理员的设备凭据。

## 范围

保留多服务器、独立消息历史、按 ID 的最新状态、手机卡片编辑、Web 手动发送、暂停与撤销。账号注册/找回、分组管理、细分授权、配置云备份和自由拖动布局后移。

内部继续保留持久队列、幂等、版本校验和来源隔离。真实 APNs 使用本产品身份，由正式安装程序在安装时写入。普通用户不在 Web 填写 Apple 私钥，只在官方 App 填写服务器地址并创建连接。桌面小组件刷新受 iOS 系统调度约束，不承诺每 60 秒桌面重绘。自建服务器直接连接 Apple APNs，不经过中央网关。
