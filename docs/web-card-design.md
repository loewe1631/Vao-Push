# Web 卡片设计、订阅与手机微调

设计背景与扩展方向。当前范围以[工作台说明](card-studio-api.md)和[实现概览](implementation.md)为准；既有接入见[简单接入](simple-onboarding.md)。

## 已确认的产品行为

Web 完成一张可直接使用的卡片，手机通过链接、二维码或订阅码添加，预览并保存后在系统桌面选择。手机无需重新排版；用户可做可选的本机微调。

Web 同时提供可视化编辑和代码编辑。用户可以把生成说明交给自己使用的 AI，将生成的卡片代码粘贴到 Web，校验、预览后继续调整或发布。两种编辑方式操作同一份卡片描述。

行情列表是通用列表的一个案例：每行左侧名称/成交额，中间价格/换算值，右侧涨跌幅色块。相同能力也用于任务进度、设备状态、天气和业务指标。Web 工作台支持将自有数据配置为可设计、可发布和可订阅的卡片。

## 四项资源分开

| 资源 | 保存位置与职责 | 更新规则 |
| --- | --- | --- |
| 数据源与最新数据 | 服务端；接收外部上报，或由连接器读取用户API并映射字段 | 更新数值与时间，不重置设计 |
| 已发布卡片模板 | 服务端；布局、字段绑定、样式及尺寸适配 | 发布后产生明确版本，供订阅设备同步 |
| 手机卡片订阅 | 每个连接/设备下的卡片引用与读取授权 | 跟随对应服务器的指定卡片，不能串用其他来源 |
| 本机微调 | 手机；用户明确改动的显示参数 | 不写回Web模板，不影响其他设备 |

显示结果由“已发布模板 + 本机微调 + 最新数据”共同决定。没有微调时直接使用Web完整设计。不要把整份模板复制后当成无来源的本地配置，否则后续无法区分Web更新与用户改动。

## 操作流程

1. Web 选择已接入的数据，查看字段、类型及示例；或配置新的 API 数据源。
2. 选择目标尺寸，在画布组合行、列、网格、文字、指标、列表、图片及可用图表；绑定字段，设置条件颜色、格式、间距等。
3. 在小、中、大及适用的iPad超大尺寸预览。保存草稿不会立刻改变手机已发布卡片；发布生成一个新版本。
4. Web 给出卡片链接、二维码或订阅码。客户端“添加卡片”提供“导入订阅卡片”，识别服务器，显示来源、预览和读取范围后保存。
5. 用户通过系统把 Vao Push 小组件添加到桌面，选择已保存卡片。导入不能绕过系统步骤直接放置桌面组件。
6. 数据或已发布设计变化后，设备按授权同步；卡片不要求反复输入码。用户可以进入手机微调，也可以恢复跟随Web设计。

卡片订阅与默认消息接收列表分别配置。设备可以只订阅某张卡片，不接收常规提醒；Web临时消息也不能隐式改变卡片订阅。

## 手机微调与模板更新建议

支持手机微调。首版建议允许名称、字段别名、显隐/顺序、小数位、单位、主题及受支持的字号参数；具体可调项由模板明确声明，手机不必重建Web编辑器。

每个组件和可调参数使用稳定标识，保存“改了哪一项”，而不是再次保存整套排版。建议采用下列规则，须通过原型验证后冻结：

- 仅数据改变：保持模板及所有本机微调。
- Web 发布兼容的设计更新：未微调的项目跟随Web，已微调的项目保留本机值。
- 手机点“恢复跟随Web”：清除该项或全部微调，使用当前已发布模板。
- 模板删除字段、改变类型或使用旧客户端不支持的组件：不静默清空微调；保留可用版本并提示。缺失或过期数据明确标示，不能冒充实时值。
- 一台手机的微调不改变其他设备。原有纯本地卡片继续保留，迁移前不得悄悄覆盖。

例如Web模板把涨跌幅放右侧并保留两位小数；手机A只将标题改成“我的行情”，手机B未修改。Web以后调整行间距，两台都跟随；A的标题继续保留。若A又修改小数位，该项也仅影响A。

## 可视化编辑与 AI 代码导入

工作台采用版本化 JSON 描述卡片。代码描述受支持的原生组件、布局及数据绑定，不执行JavaScript、Swift或任意网页代码。Web预览与iOS原生渲染遵守同一组件规则；尺寸、字体和系统渲染差异需要实测，不能承诺任意HTML/CSS像素一致。

代码导入流程：粘贴/上传描述 → 语法与结构校验 → 字段/组件/尺寸兼容检查 → 预览 → 可视化调整 → 发布。错误应指出路径或行列，不能跳过不支持的配置后声称完整导入。可视化和代码切换不得丢失已支持的样式。

Web 可提供“复制AI生成说明”：包括卡片描述版本、可用组件、尺寸约束、字段结构和示例。用户将其交给自己选择的模型即可生成代码；生成说明不包含上游API密钥。接入内置模型调用不是代码导入的前提。

以下为v1格式示例；完整结构和当前限额见[JSON Schema](card-design.schema.json)与[工作台说明](card-studio-api.md)：

```json
{
  "schema_version": 1,
  "name": "行情列表",
  "family": "medium",
  "layout": {
    "id": "quotes",
    "type": "list",
    "source": "items",
    "limit": 3,
    "row": {
      "id": "quote_row",
      "type": "row",
      "children": [
        { "id": "symbol", "type": "text", "bind": "fields.symbol" },
        { "id": "price", "type": "number", "bind": "fields.price", "decimals": 2 },
        { "id": "change", "type": "badge", "bind": "fields.change", "format": "percent", "color_rule": "signed" }
      ]
    }
  }
}
```

字段绑定引用整理后的标准字段；条件和格式使用已定义的规则，不引入任意表达式执行。节点层级、数量、图表点数和尺寸容量需要有明确上限，以原型的资源与可读性验证确定。

## API 数据接入与访问范围

当前上游上报继续支持，同时支持公网 HTTPS GET JSON 读取、必要鉴权、字段/列表映射、采集周期、成功时间与失败原因；具体类型转换范围见工作台说明。业务阈值和完整交易策略不因此自动纳入范围。

上游地址及密钥由服务端连接器使用。手机只获得展示数据和卡片配置。发布卡片不默认公开其数据；订阅码用于建立受限读取关系，不复用消息发送Key。

完整链接可携带服务器定位信息；短码须在明确的服务器下解析。导入后换取与设备绑定的只读订阅，支持到期/撤销；码的有效期、使用次数和设备范围需在发布界面可解释。换发导入码不应改变卡片标识或破坏已有有效订阅。

现有数据按设备内部作用域隔离，不能仅给其他设备同一个data_id就视为可读取。需要新增服务端卡片资源、数据引用和逐设备授权；公开模板共享与私有数据订阅分开。布局发布版本、数据revision与本地微调版本独立记录。

## 分阶段实施与验收建议

1. 定义描述格式及原生渲染，复现三行行情，同时完成任务进度等非金融案例；验收多尺寸及可访问性，不依靠图片截图替代原生字段。
2. 建立服务端卡片草稿/发布、订阅与读取授权，客户端导入；同时验证模板更新和本机微调的合并、恢复及撤销。
3. 建立Web可视化/代码编辑、校验、预览及AI生成说明；从粘贴代码到手机桌面展示走完闭环。
4. 接入HTTP JSON连接器与字段映射，和现有上报使用相同数据层；验证错误、重试、过期与凭据隔离。

当前接口、描述限额和微调项见工作台说明。真实APNs、Widget后台刷新和交互仍需真机；任何导入码或Web编辑能力都不改变iOS的刷新调度限制。

平台依据：[WidgetKit支持的视图](https://developer.apple.com/documentation/widgetkit/swiftui-views)、[WidgetKit推送更新](https://developer.apple.com/documentation/widgetkit/updating-widgets-with-widgetkit-push-notifications)。
